# 年次データ更新の手順

**⚠️ 2026年9月11日判明：更新時期を10月末→3月末に変更**
総務省の公表スケジュールを確認したところ、主要財政指標一覧は決算年度の翌々年12月頃、決算カード・決算状況調は翌々年2〜3月頃の公表だった。10月時点ではまだ新年度データが存在しないため、**すべてのデータが出揃う3月末にまとめて実施する**方針に変更した。

年次更新は **3月末**（メイン更新）と、その後の**確認作業**の2段階です。
ふるさと納税のデータだけは、総務省の公表時期に合わせて **8月** に別で更新します（下の「【8月】ふるさと納税の更新」）。

---

## 【3月末】メイン更新

### ① 総務省サイトで新年度のExcelを探す（Claudeに手伝ってもらう）

Claudeに「今年のデータに更新して」と声をかければ、以下6種類のExcelのURLを一緒に探してくれます：

1. 全市町村・全都道府県の主要財政指標一覧
2. 基金残高等一覧（財政調整基金）
3. 住民基本台帳人口・人口動態
4. 市町村別・都道府県別決算状況調（歳出歳入・実質赤字比率・連結実質赤字比率も同じファイルに含まれる）
5. 目的別歳出内訳
6. 住民基本台帳年齢階級別人口

### ② `scripts/config.json` を書き換える

GitHubアプリで `scripts/config.json` を開き、鉛筆アイコンで編集。
各URLを新しいものに書き換えて、一番上の `fiscal_year_label` と `population_year_label` も新年度に更新してコミット。

> ⚠️ この2つの年は、過去データを「どの年の欄に入れるか」を決めるのにも使います（2026-09-29〜）。
> 書き換え忘れなどで年が合わないときは、データを壊さないよう更新が赤い×で止まります。
> そのときは config.json の年を確認してください。

```json
{
  "fiscal_year_label": "令和7年度",     ← ここを書き換え
  "population_year_label": "令和8年",   ← ここを書き換え
  "fiscal_indicators": {
    "muni": "https://www.soumu.go.jp/main_content/新しい番号.xlsx",
    ...
  }
}
```

### ③ ワークフローを実行

https://github.com/ray-ray870/mitchie-fiscal/actions/workflows/update-data.yml で「Run workflow」を実行。
安全設計により、検証に成功した場合のみ自動コミットされます。

### ③.5 デプロイを手動で実行

https://github.com/ray-ray870/mitchie-fiscal/actions/workflows/deploy-with-check.yml
で「ワークフローの実行」を実行します。

⚠️ **この手順を忘れると、データは更新されているのにサイトに反映されません。**

GitHubの仕様上、ワークフロー（bot）がコミットした変更は別のワークフローを起動しません。
`update-data.yml` はbotがコミットするため、公開処理が自動で走らないためです。

1〜2分で公開されます。

### ④ index.htmlの年度表記を手動更新

index.html内に直接書かれている「令和6年度」のような年度表記（吹き出しメッセージ、各指標の出典表記、起債許可団体等のバッジ表示など）を、新しい年度に手動で書き換えてコミット。

### ⑤ OGPメタタグ内の自治体数を手動更新

index.html の `<head>` 内にある以下2箇所は、SNS（X・LINEなど）でリンクを共有した際のプレビュー文言に使われる静的なテキストのため、自動更新されません。市区町村の合併・新設などで対応自治体数が変わった場合は、実際の件数に合わせて手動で書き換える。

```html
<meta property="og:description" content="全国1,786自治体の財政をチェック！みっちーが財政健全度を診断します🐧">
<meta name="twitter:description" content="全国1,786自治体の財政をチェック！みっちーが財政健全度を診断します🐧">
```

**加えて、トップページの「📊 約1,786自治体対応」バッジ（`<span id="municipality-count2">1,786</span>`）も同様に手動更新が必要。**
こちらはJS読み込み後に実際の件数へ自動で上書きされるが、その初期値（JSが動かない場面・SNSクローラーなどで見える可能性がある値）は静的にハードコードされているため、上記2箇所と合わせて書き換える。

※ アプリ内の共有ボタン（X/LINEでアプリをおすすめする！）の文言自体は、実際に読み込んだデータ件数から自動生成されるため、こちらの対応は不要。

### ⑥ Myみっちー機能一式をapply（初回公開時のみ）

2026年9月に実装・preview確認済みのMyみっちー機能（本体・個別ページのスコア枠変更・比較機能連携・全国のみっちー機能）を、このタイミングで初めて本番公開する。**共有画像の順位表示・Xシェア文言の変更は別件で9月中に本番反映済みのため、ここでは対応不要。**

1. https://github.com/ray-ray870/mitchie-fiscal/actions/workflows/mymitchie.yml で「Run workflow」→モードで **apply** を選んで実行
2. 再び `deploy-with-check.yml` を手動実行
3. 本番サイトで動作確認（新年度データでの順位表示になっているか）
4. 確認できたら、使い終わった `scripts/refactor_mymitchie.py`・`scripts/mymitchie_html.txt`・`scripts/mymitchie_css.txt`・`scripts/mymitchie_js.txt`・`.github/workflows/mymitchie.yml` を削除

詳しい仕様は `SPEC.md` の該当章（Myみっちー機能／個別の自治体ページのスコア枠／比較機能との連携／全国のみっちー機能）を参照。**この⑥は初回公開時のみの手順。** 一度applyしたら、翌年以降の年次更新ではMyみっちー自体はコードに組み込まれているので不要（通常のデータ更新だけで新年度の順位に自動で追従する）。

## 【8月】ふるさと納税の更新

ふるさと納税の数字（受入額・住民税控除額）は、3月末の年次更新には**含まれません**。総務省が毎年**7月末〜8月初め**に「ふるさと納税に関する現況調査結果」を公表するので、そのあとに別で更新する。

### ① 総務省サイトで新年度のExcelを2つ探す（Claudeに手伝ってもらう）

Claudeに「ふるさと納税を今年のデータに更新して」と声をかければ、URLを一緒に探してくれます。必要なのは次の2つだけ：

1. **各自治体のふるさと納税受入額及び受入件数（平成20年度～令和X年度）** … 全年度の推移が1ファイルに入っている
2. **各自治体の令和Y年度課税における住民税控除額等** … 最新の1年分（Y = X + 1）

※ 過去の控除額ファイルは不要。今のデータの過去7年分を1年ずらして使う。

### ② ワークフローを実行

https://github.com/ray-ray870/mitchie-fiscal/actions/workflows/furusato-update.yml で「Run workflow」を押し、2つのURLを貼り付けて実行。

- `preview/data-*.json` と `preview/js/ui.js`（グラフの年度ラベル）が自動で更新される。本番には触らない
- 自治体名が1件でも合わない、年度が合わない、などのときは止まって何も書き込まない（ログの「NG:」の行を Claude に見せる）

### ③ プレビューで確認

https://ray-ray870.github.io/mitchie-fiscal/preview/ で、いくつかの自治体のふるさと納税の詳細を開き、グラフの年度（右端が新年度になっているか）と数字を確認。同名自治体（伊達市（北海道）・朝日町（山形）など）も見ておく。

### ④ 本番に反映

1. 「プレビューのデータを本番に反映」を実行
2. 「プレビューを本番に反映」を実行（ui.js の年度ラベルを反映するため）

### 注記（指定取消しなど）の追加

返礼品の基準違反などで自治体がふるさと納税の対象から外れたときは、`scripts/furusato_notes.json` に1件足して、もう一度②を実行する（同じURLのままでよい。同じ年度で再実行しても数字は変わらず、注記だけ反映される）。

### データが壊れたときの作り直し

控除額の8年分をすべて総務省のExcelから作り直す場合は、`scripts/build_furusato.py` を `--full` 付きで実行する（Excel 9つが必要なので、Claude に頼んで実行してもらう）。

処理スクリプト：`scripts/build_furusato.py`（注記：`scripts/furusato_notes.json`、自動記録：`scripts/furusato_config.json`）

## 【11月末】確認のみの軽い更新

総務省が毎年11月末頃に公表する「健全化判断比率・資金不足比率の概要（確報）」PDFを確認し、**都道府県が実質赤字比率・連結実質赤字比率で基準超えになっていないか**を照合する。

- 確認先：https://www.soumu.go.jp/main_sosiki/c-zaisei/kouei_kessan.html の「決算の概要（速報）」欄
- 確認する内容：都道府県（47団体）が引き続き「早期健全化基準以上の団体はなし」となっているか
- 該当があった場合のみ、Claudeに伝えて個別対応（ファイルの再取得は基本的に不要）

## 起債許可団体・早期健全化団体・財政再生団体の判定基準

| 指標 | 早期健全化基準 | 財政再生基準 |
|---|---|---|
| 実質赤字比率 | 都道府県3.75% / 市町村11.25〜15% | 都道府県5% / 市町村20% |
| 連結実質赤字比率 | 都道府県8.75% / 市町村16.25〜20% | 都道府県15% / 市町村30% |
| 実質公債費比率 | 25%（共通） | 35%（共通） |
| 将来負担比率 | 都道府県・政令市400% / 市町村350% | 基準なし |
| 起債許可団体 | 実質公債費比率18%以上（共通） | ― |

- 市町村分の実質赤字比率・連結実質赤字比率は「決算状況調（概要）」ファイルに含まれる列（36列目・37列目）から取得（新規ファイル取得は不要）
- 都道府県分の実質赤字比率・連結実質赤字比率は、単体のExcelファイルが総務省から一般公開されていないため、11月末の確報PDFで代替確認する運用としている
- 実質公債費比率・将来負担比率は市町村・都道府県とも既存データからそのまま判定可能

処理スクリプト：`scripts/update_fiscal_data.py`
